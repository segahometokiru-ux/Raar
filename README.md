# OUR STORY

Личный романтический сайт-подарок: письмо, фотогалерея, временная линия и финальный экран. Это статический сайт на HTML, CSS и JavaScript — без сервера, базы данных, сборки и сбора данных о посетителях.

## Быстрый запуск

Откройте `index.html` в современном браузере или опубликуйте проект на GitHub Pages. Для локального просмотра можно также запустить любой статический сервер, например расширение Live Server в редакторе. Установка зависимостей не требуется.

## Персонализация

### Письмо и история

Откройте `script.js` и отредактируйте в начале файла:

- `LETTER_PARAGRAPHS` — абзацы письма;
- `LETTER_SIGNATURE` — подпись;
- `GALLERY_ITEMS` — подписи и альтернативный текст фотографий;
- `STORY_ITEMS` — даты, названия событий и воспоминания.

Поля истории по умолчанию пусты, чтобы не придумывать ваши даты и события. Заполните элементы массива `STORY_ITEMS` своими словами; пустые записи не показываются. Текст вставляется безопасным способом через `textContent`.

### Фотографии

Положите свои снимки в `images/` и назовите их строго `photo1.jpg`, `photo2.jpg`, …, `photo10.jpg`. Используйте JPEG-файлы и соответствующие пути уже указаны в `script.js`. Если снимка пока нет, карточка покажет декоративную заглушку, а не случайное фото. Можно заменить подписи рядом с путями в `GALLERY_ITEMS`. Нажатие на карточку открывает полноэкранный просмотр; кнопки и клавиши ←/→ переключают снимки, Escape закрывает просмотр.

### Музыка

Создайте папку `audio/`, добавьте свою композицию с именем `our-song.mp3` и загрузите её в репозиторий. Кнопка «Музыка» включает и выключает трек. Воспроизведение начинается только по нажатию пользователя, как того требуют браузеры и Telegram. Пока файл не добавлен, кнопка объяснит, что нужно сделать.

## Публикация через GitHub Pages

1. Загрузите файлы проекта в корень репозитория и отправьте commit в GitHub.
2. Откройте репозиторий → **Settings → Pages**.
3. В **Build and deployment** выберите **Deploy from a branch**.
4. Выберите ветку, в которую загрузили сайт (например, `main`), и папку **/(root)**, затем нажмите **Save**.
5. Дождитесь публикации и откройте ссылку, отображаемую в разделе Pages. Обновления сайта публикуются после новых commits.

Все локальные ссылки относительные, поэтому сайт работает как в корне домена, так и в проектном подпути GitHub Pages. Никаких секретов, токенов, платных сервисов или серверной настройки нет.

## Подключение Telegram Mini App

1. Опубликуйте сайт по HTTPS через GitHub Pages.
2. Создайте бота через [@BotFather](https://t.me/BotFather) и укажите адрес опубликованного сайта как Web App URL (например, в настройках Main Mini App или кнопки меню).
3. Откройте ссылку Mini App внутри Telegram. В `index.html` подключён официальный `telegram-web-app.js`; приложение вызывает `ready()`, `expand()` и согласует цвета шапки и фона с дизайном. Отступы учитывают `safe-area-inset-*`, интерфейс адаптируется под мобильный viewport.
4. Для проверки откройте опубликованную HTTPS-страницу в Telegram на телефоне. В обычном браузере сайт также работает, Telegram SDK там просто не активен.

Mini App не использует Telegram API для чтения или отправки личных данных. Расширение на весь экран ограничено возможностями и настройками конкретной версии Telegram; сайт корректно работает и в стандартном окне Web App.

## Файлы проекта

- `index.html` — структура страниц и подключение ресурсов.
- `style.css` — оформление, адаптивность, анимации и безопасные отступы.
- `script.js` — письмо, данные галереи и истории, конверт, просмотр изображений, музыка, анимации и инициализация Telegram.
- `images/README.md` — напоминание о фото и их именах.

Google Fonts используются только для декоративной типографики; при недоступности сети применяются системные шрифты. Telegram Web App SDK загружается с официального CDN, когда приложение открыто через Telegram. Для обычной работы сайта установка сторонних пакетов не нужна.
